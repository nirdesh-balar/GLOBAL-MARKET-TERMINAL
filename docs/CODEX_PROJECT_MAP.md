# GMT project map

The initial audit used the official `main` at `5a3c0713e08e9fbb739272f2363acfd45465b377`. Its 624 tracked files include application source, staged regression scripts, platform resources and third-party notices. This map traces primary execution paths. See [testing](TESTING.md), [build](BUILD.md), [release gates](RELEASING.md) and [storage](STORAGE.md) for established procedures.

Phase 1 Chart Grid entered official main at `3f044d65fcc3dc78177aeddcadc65e436fa4c673`. The rc.8 release-preparation revision covers version and release metadata while the installed app is rc.7. [macOS release status](MAC_RELEASE_STATUS.md)

## Startup, requests and shutdown

1. `scripts/dev.mjs` runs Vite and builds the Electron main/preload bundles with esbuild. `npm run build` checks renderer and Electron TypeScript, builds the Vite assets and compiles the native notification helper on macOS. Packaged Electron starts from `desktop/dist-electron/main.cjs`.
2. `desktop/electron/main.ts` validates platform and package identity, chooses `userData`, takes the single-instance lock, creates a sandboxed, context-isolated `BrowserWindow`, and starts one owned backend. `desktop/electron/platform.ts` resolves the Python venv in development or the frozen backend under packaged resources.
3. `backend/launcher.py` binds Uvicorn to an ephemeral loopback port and reports readiness on stdout. Electron probes authenticated `/health`. `backend/app/main.py:create_app` initializes SQLite, instrument registry, provider services, request/cache state, streaming, quotes, screeners and alerts. FastAPI lifespan owns background refresh and service closure.
4. `desktop/src/main.tsx` mounts React `App.tsx`. `desktop/src/services/api.ts` uses `window.terminal` from `desktop/electron/preload.ts`. The main process validates the invoking frame, allowlists routes and methods, and forwards JSON over authenticated loopback HTTP. The renderer can cancel obsolete requests. Main also relays market-stream, alert navigation, update and window events through IPC. File selection/export and native controls stay in main.
5. On quit, Electron allows a bounded drain of pending saves, aborts active requests, stops bridges and closes the owned backend via its private stdin protocol. `backendLifecycle.ts` contains the bounded fallback and `backend/app/parent_lifetime.py` handles parent pipe closure. FastAPI closes monitoring, streaming and analytical services.

## Charts, analytics and user workflows

| Area | Source entry points and data flow |
| --- | --- |
| Chart Grid | `desktop/src/chartGrid/` owns the independent paged workspace and lightweight candlestick renderer. Watchlist and screener handoffs preserve displayed order and canonical identity. Grid keeps eight visible instances at most, a two-lease queue and no per-card streams or timer-driven refresh. It shares `services/api.ts`, the history service and existing provider budgets. `models.py` validates Grid preferences, and `main.py` hydrates exact catalogue metadata for the renderer. |
| Workspace and chart layout | `desktop/src/App.tsx` owns workspace, active pane, responsive navigation and chart visibility in React state. It loads `/health`, `/workspace` and `/api/indices`, then debounces workspace saves and serializes watchlist mutations. `charts/ChartPane.tsx` renders Lightweight Charts series, controls the price scale, and broadcasts visible-range and crosshair synchronization. Layouts use 1/2/4/6/8 panes. `charts/ReplayControls.tsx` and `ChartPane.tsx` use a frozen candle prefix and restore the viewport on exit. |
| History and live data | `services/api.ts` shares identical requests between chart panes and releases unused requests. `/api/history` resolves canonical identity and forwards through `history.py` and `market_router.py`. History uses bounded RAM caches, request budgets, coalescing, and market-session-aware normalization/aggregation. `providers/yahoo.py` adapts non-crypto via `yfinance`. `providers/hyperliquid.py` verifies catalogue and REST candles for explicit spot/perpetual identities. `hyperliquid_stream.py` manages demand, WebSocket subscriptions, events and recovery. Electron polls cursor-based events and `desktop/src/streams` merges frames into chart and watchlist views. Saved Yahoo crypto identities require explicit migration via `crypto_migration.py`. NSE metadata and user-selected historical imports have distinct roles. |
| Indicators | `desktop/src/components/indicatorLibrary.ts` and Indicator Manager/Settings define catalog and configuration UI. `desktop/src/charts/{indicators,trend,momentum,volume,custom}.ts`, study layout/primitive modules and reference hooks compute and render chart studies. `backend/app/indicators.py` and the corresponding Python indicator modules power `/api/indicators/calculate` and analytical consumers. `reference_context.py` resolves supporting series and market sessions. Registry regression checks cover 69 studies. |
| Drawings | `charts/useDrawings.tsx` and `charts/Drawings.ts` implement chart gestures and primitives. `drawings/{registry,coordinates,interactions,geometry,codec,storage}.ts` define tools, transform time/price anchors, edit geometry, and encode per-instrument/timeframe drawing sets. Workspace persistence stores drawing configuration and anchors. `drawing_analytics.py` supplies backend drawing calculations. Registry checks cover 86 enabled tools. |
| Watchlists and discovery | `components/{Search,WatchlistSidebar,IndexWatchlist}.tsx`, `watchlists/`, `flags/` and `refresh/` drive discovery, selection, sorting, quote refresh and flags. `registry.py`, `discovery.py`, `watchlists.py`, `flags.py` and `refresh.py` handle identity, revisioned transactions and quote batching. `desktop/electron/{watchlistFiles,excelExport}.ts` implement native dialogs with CSV and XLSX validation/export. |
| Screener and alerts | `desktop/src/screener/ScreenerPage.tsx` coordinates universe, conditions, progress, presets and results. `screener.py`, `screener_conditions.py` and `live_analysis.py` run async jobs and evaluate studies. Regression checks cover 59 conditions. `desktop/src/alerts` edits and displays rules, runtime state and history. `alerts.py`, `alert_store.py` and `live_alerts.py` evaluate rules and persist events. `alertNotifications.ts` handles desktop delivery and routes notification clicks back to charts. |
| Profiles and settings | `database.py`, `models.py`, `profile_paths.py` and `profile_security.py` define SQLite/profile and workspace serialization boundaries. `terminal.sqlite3` holds settings, chart/drawing state, watchlists, catalogue/flags, screener presets and alert data. `restore_workspace` handles older records. Updater preferences live in `application-updates.json`. Users choose where to save CSV, XLSX and screenshots. OHLCV caches are in memory. |

## Platform and release modules

- **Shared code** includes React/TypeScript and Lightweight Charts, preload/IPC contracts, Python 3.11/FastAPI analytics, provider logic and data models. Native scripts live outside shared market and calculation code.
- **macOS arm64** uses `desktop/native/notification_status.mm` and `scripts/build-notification-native.mjs` for the notification status bridge. Fullscreen uses a native Mac accelerator. `scripts/package-public-mac.mjs` freezes Python with PyInstaller, then builds DMG/ZIP with `build/public-mac.config.cjs`. `build/public-after-sign.cjs` performs signing checks. `desktop/electron/{updates,updateRuntime}.ts` manages the official stable feed, trusted signing requirement, prerelease/downgrade policy and explicit restart. Candidate signing and metadata are covered in [Mac release status](MAC_RELEASE_STATUS.md).
- **Windows x64** uses `scripts/build-windows-backend.ps1` and `backend/windows-backend.spec` to freeze `imt-backend.exe`. `scripts/package-personal-win.ps1` validates AMD64 PE and builds the NSIS installer via `build/personal-win.config.cjs`. Windows uses F11, the Windows icon and the personal package identity with updates disabled. Version-specific portable helpers keep a local `GMT-Portable-Data` tree. See [Windows pending](WINDOWS_PENDING.md).
- **CI** runs source regressions on pull requests and pushes to `main` in `.github/workflows/public-source-ci.yml`. It runs all numerical and UI fixtures and returns a failing status for any failed script. `macos-arm64-candidate.yml` is a manual candidate build at a pinned SHA. `approved-draft-release.yml` is a separately authorized, manual release gate.

## Test structure

- `backend/tests` uses pytest with FastAPI TestClient, injected fixtures and reference data for indicators, drawings, streams, watchlists, alerts, history, screener, provider policy, and workspace migration.
- `scripts/verify-macos.mjs` coordinates numerical and serial Playwright/Electron fixture tests. `scripts/isolated-electron.mjs` validates package identity and temporary-profile containment before launch. `test-baselines/` tracks registry snapshots, sidebar geometry, and macOS performance reference data.
- `test:platform`, `test:package:config`, `test:release` and `scripts/version-consistency-test.mjs` cover platform configuration, packaging and update policy, and core source version agreement. Historical stage scripts can depend on older versions, private fixtures or paths. Check each script before launch. Live providers, packaged startup, native notifications and trusted updates each need their own evidence.
