# Release gates

The only destination is nirdesh-balar/GLOBAL-MARKET-TERMINAL. Immediately before each remote write, verify authenticated user nirdesh-balar and repository owner/id. Never infer an asset exists from its intended URL. Current local work has not pushed source, changed repository settings or run remote CI.

1. Review the clean source file/hash manifest, secret/path scan and all history reachable from the proposed public branch. Preserve private original checkpoints separately. Approve the proposed MIT license and third-party notice obligations.
2. Authorize the exact source commit for publication and Windows CI. Use read-only CI tokens and persist-credentials:false. Pull requests receive no release/signing secrets.
3. Build both native candidates. Verify real installer behavior, identity, source/build fingerprints and SHA-256/SHA-512 manifests. Record signing/notarization limits honestly.
4. Complete Windows 11 desktop checks and real signed A-to-B updates independently on both platforms. Existing v0.7.0 users require one manual installation.
5. Configure a restricted public-release GitHub environment with required owner review and main-branch deployment rules. Protect main with required CI/review, block force pushes/deletion, and enable Issues/private security reporting where available. These settings require a separately approved remote change; YAML alone does not prove they exist.
6. Approve the exact release assets/source tag v1.0.0. Use a protected owner-authenticated release token only for the manual publishing job. The release script refuses incomplete acceptance or signing records. No PR, branch push or tag automatically publishes.
7. Upload an approved draft, inspect actual assets/metadata, then request/record final stable-publication approval. Verify downloaded bytes of both public installer URLs against the approved manifest before adding direct README download links.

Stable filenames are GLOBAL-MARKET-TERMINAL-mac-arm64.dmg and GLOBAL-MARKET-TERMINAL-win-x64-Setup.exe. Include the actual mac updater ZIP/latest-mac.yml and Windows latest.yml/blockmaps generated by the pinned toolchain, plus checksums, notes and installation guides. Never handwrite update hashes. Do not distribute a missing platform, an unsigned build as trusted, or an untested cross-platform stable release.

The updater validates the fixed official feed and native signing, rejects prereleases/downgrades, lets charts continue during background transfer, and installs only after an explicit user restart. Six-hour checks and manual checks are bounded; no auto-install-on-quit is enabled. Candidate metadata keeps unsigned builds blocked. Native A-to-B acceptance is still UNVERIFIED.
